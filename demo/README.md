# Nexora CRM — демо-стенд

Статичный мок продукта для показа клиентам: без базы данных, без API с реальной
бизнес-логикой. Все данные — TS-фикстуры в `demo-data/`, состояние живёт в React
state и не сохраняется между перезагрузками (кроме cookie авторизации).

## Запуск локально

```bash
npm install
cp .env.example .env.local   # заполнить значения
npm run dev                  # http://localhost:3100
```

## Переменные окружения

| Переменная | Описание |
| --- | --- |
| `DEMO_PASSWORD` | Пароль для входа через форму на `/login` |
| `DEMO_TOKENS` | Персональные токены лидов: `токен:метка,токен2:метка2`. Вход по ссылке `/login?token=<токен>` ставит httpOnly cookie на 72 часа |

Срок жизни сессии настраивается константой `SESSION_TTL_HOURS` в `lib/auth.ts`.

## Деплой на Vercel

1. Создать отдельный проект, **Root Directory: `demo`**.
2. Задать `DEMO_PASSWORD` и `DEMO_TOKENS` в Environment Variables.
3. Привязать домен `demo.nexorasystems.kz`.

Индексация запрещена на трёх уровнях: `meta robots`, `X-Robots-Tag` и `/robots.txt`.

## Структура

- `proxy.ts` — middleware: защита всех роутов, вход по токену из query
- `demo-data/` — фикстуры (заявки, партнёры, мастера, склад, акты, лицензия)
- `lib/status-machine.ts` — конечный автомат статусов заявки (граф в конфиге)
- `lib/store.tsx` — состояние демо и все действия над моком
- `lib/finance.ts` — единые правила расчёта прибыли/комиссии/выплат
- `app/(demo)/(desktop)/…` — модули CRM, `app/(demo)/mobile/…` — вид мастера
- `app/act/[token]` — публичная страница акта (без авторизации)
